## 공을 잘라내는 단계에서 생긴 문제

SportsBall은 화면에서 공의 위치와 배경이 제각각입니다. 윤곽과 바운딩 박스로 공이 있을 영역을 자른 뒤, HOG와 색상 히스토그램을 추출해 분류기에 전달했습니다. 공 대신 배경이 잘리면 두 특징 모두 엉뚱한 영역을 요약합니다. 팀 보고서는 이런 오분류를 확인했고, XGBoost의 교차검증 정확도와 별도 테스트 정확도를 각각 약 65%, 약 37%로 기록했습니다.

개인 실험에서는 경계 검출, 밝기 보정, 형태학적 처리의 순서를 바꿔 잘라낸 영역을 비교했습니다. HOG는 획이나 경계의 방향을, 색상 히스토그램은 관심 영역 안의 색 분포를 요약합니다. 그래서 분류 결과를 볼 때 원본, 전처리 결과, 최종 잘라낸 영역을 함께 확인했습니다.

## 전처리 순서를 바꿔 본 실험

개인 실험에서 본 문제는 공의 윤곽이 약하거나 배경에 강한 모서리가 있으면 관심 영역이 공 대신 배경으로 잡힌다는 점이었습니다. 관심 영역 크기를 64×64에서 128×128로 키우거나 증강을 적용해도 이미 잘못 잘린 입력에는 공의 특징이 들어오지 않습니다. 그래서 같은 종류의 전처리를 적용하는 순서를 바꿔 비교했습니다.

| 실험 단계 | 팀 보고서에 기록한 탐색 결과 |
| --- | --- |
| 밝기 보정 → 형태학적 경계 강조 → 자동 Canny | 약 35% |
| 자동 Canny → 밝기 보정 → 형태학적 경계 강조 | 약 45% |
| ROI에서 HOG와 색상 히스토그램을 뽑아 분류 | 내부 탐색에서 최대 약 65% |
| 최종 고전적 분류 후보의 별도 테스트 | 약 37% |

앞의 두 값은 전처리 순서를 찾는 과정의 탐색 결과입니다. 마지막 줄의 별도 테스트는 그 과정에서 본 점수가 새 사진에서도 유지되는지 확인하기 위한 평가입니다. 그림에서 공 대신 배경이 선택된 사례는 분류 결과만 봐서는 구별하기 어렵습니다. 원본과 잘라낸 영역을 함께 붙인 이유입니다.

## CNN이 배운 특징을 확인하는 방법

CNN의 중간 특징을 뽑아 t-SNE로 2차원에 투영하고 정답 클래스에 따라 색을 입혔습니다. MNIST에서는 같은 색이 모이는 구간이 뚜렷했고, SportsBall에서는 클래스가 더 많이 섞였습니다. 그림으로 어느 클래스가 겹치는지 살피고, 성능 비교는 별도 평가 수치로 읽었습니다.

![MNIST와 SportsBall의 중간 특징을 t-SNE로 시각화한 팀 실험 자료](https://raw.githubusercontent.com/gidaseul/machine-learning-project/aec5241d83d14d8fe95837cd30c278b170c3239b/assets/images/representation-latent-evidence.png)

팀의 CNN 보고서는 럭비공 특징에 반응한 예와, 공이 사진에서 작거나 주변 물체가 크게 보일 때 반응이 넓게 퍼진 예를 비교했습니다. 잠재 공간 그림으로 여러 클래스가 섞이는 구간을 보고, 개별 히트맵으로 어떤 부분에 반응했는지 확인했습니다. 그 결과 같은 클래스 안에서도 촬영 구도가 달라지면 특징이 달라질 수 있다는 가설을 세울 수 있었습니다.

## 평가 결과를 비교하는 법

MNIST에서 HOG+SVM은 내부 검증 95.56%, 별도 테스트에서 50장 중 47장인 94%를 기록했습니다. SportsBall의 교차검증과 별도 테스트 차이는 입력 처리와 데이터 차이를 더 살펴볼 이유입니다. t-SNE에서 점이 모이거나 겹치는 모습은 어떤 클래스가 어려운지 탐색하는 데 쓰고, 분류 성능은 평가 수치에서 판단합니다.

CNN 팀 보고서의 기준 모델은 MNIST 별도 테스트에서 98%, SportsBall에서 48%를 기록했습니다. SportsBall의 다음 실험에서는 같은 분할을 고정하고, 원본 전체를 넣는 기준 모델과 사람이 관심 영역을 확인한 입력을 비교할 수 있습니다. 정답 ROI를 썼을 때도 틀리는 사진과 잘못 자른 사진을 구분하면 관심 영역 추출에 시간을 더 쓸지, 분류기의 표현을 개선할지 결정할 수 있습니다.

공개 CNN 노트북 일부에서는 테스트 손실로 체크포인트를 선택했습니다. 독립 성능을 다시 측정하려면 학습에서 검증 세트를 분리하고, 테스트 세트는 모델 선택이 끝난 뒤 평가합니다. ROI 개선 효과도 같은 분할에서 원본 이미지 기준 모델과 비교해야 분리해 볼 수 있습니다. [재현 시 유의점](https://github.com/gidaseul/machine-learning-project/blob/main/ML_2/README.md#notes-before-reproducing)
