## 문제와 담당 범위

과수원 전체를 살필 때는 어떤 구역을 먼저 확인할지가 중요합니다. 개별 잎을 선택한 뒤에는 어떤 병해가 의심되고 AI가 무엇을 보고 그렇게 판단했는지를 알아야 합니다. 팀은 진단 파이프라인을 구성했고, 저는 그 결과를 구역·잎 단위로 탐색하면서 판단 근거를 비교할 수 있도록 화면을 설계했습니다.

구역 화면에서 우선순위를 정하려는 사람과 한 잎의 진단을 확인하려는 사람은 서로 다른 정보가 필요합니다. 과수원 화면에는 구역별 위험도와 병해 분포를, 상세 리포트에는 원본 사진과 모델 출력, 유사 잎을 배치했습니다. 구역 화면은 확인할 대상을 고르는 데 쓰이고, 잎 화면에서는 그 판단에 사용된 근거를 살펴볼 수 있습니다. 공개 데모의 구역 지표는 준비된 시나리오 데이터이며 개별 잎 화면은 저장된 모델 출력을 보여줍니다.

## 대시보드에서 진단 근거를 확인하는 경로

```text
공개 데모
├── /analysis        과수원 구역 위험도, 병해 필터, 대표 잎 목록
├── /report          구역별 검출 결과와 대표 잎 근거 묶음
├── /leaf            선택한 잎의 분류, 유사 사례, Grad-CAM, 리포트
└── /analyze         새 잎 사진을 업로드하는 화면
    └── /api/infer   파일을 분리된 FastAPI 추론 서버로 전달
```

구역을 살피는 화면과 개별 잎을 분석하는 화면은 역할이 다릅니다. 저장된 사례는 구역에서 잎으로 들어가 비교할 수 있습니다. 새 업로드는 웹 서버가 파일을 추론 서버로 전달하고, 응답을 받아 결과를 표시하는 흐름입니다.

대시보드 코드에서 화면은 `app/analysis/page.tsx`, `app/report/page.tsx`, `app/leaf/page.tsx`로 나뉩니다. `lib/orchard-data.ts`에서 구역과 잎을 연결하고, 저장된 진단은 `lib/survey-data.ts`에서 읽습니다. 업로드는 `app/analyze/page.tsx`에서 시작해 `app/api/infer/route.ts`를 거칩니다.

## 저장된 사례와 새 사진의 데이터 흐름

| 보는 작업 | 화면에서 일어나는 일 |
| --- | --- |
| 구역 비교 | 구역별 위험도를 보고 병해를 필터링합니다. 구역 리포트에서 대표 잎을 고르면 `/leaf`가 해당 잎의 저장된 기록을 표시합니다. |
| 잎의 근거 확인 | 분류 예측, 가장 비슷한 잎, Grad-CAM, 종합 확신도를 같은 사례에 맞춰 보여줍니다. |
| 새 사진 분석 | `/analyze`가 이미지 파일을 `/api/infer`로 보내고, 웹 서버가 연결된 FastAPI 추론 서버로 전달합니다. 추론 서버 연결 실패는 화면이 처리할 수 있는 오류 응답으로 돌려줍니다. |

이미지를 올리는 경로에서는 먼저 파일 형식을 확인하고 미리보기를 띄웁니다. 분석을 시작하면 브라우저는 사진을 폼 데이터로 보내고, Next.js API가 추론 서버에 파일을 전달합니다. 결과가 도착하면 예측과 근거를 화면에 표시합니다. 요청에 파일이 없거나 서버가 연결되지 않으면 오류를 표시해 업로드 화면에서 원인을 확인할 수 있습니다. 저장된 리포트는 추론 API 응답을 기다리지 않고 구역과 잎 식별자로 조회합니다.

## 분류 점수와 근거를 함께 보여주는 이유

팀 파이프라인은 EfficientNet-B0 분류 뒤 DINOv2로 유사 잎을 찾고, Grad-CAM과 잎 마스크로 모델 반응이 잎에 놓였는지 확인합니다. 근거가 엇갈리는 사례는 추가 관찰 경로로 보낼 수 있도록 설계했습니다. 화면은 분류 점수 옆에 유사 사례 일치도와 종합 확신도를 배치했습니다.

| 근거 | 리포트에서 확인할 질문 |
| --- | --- |
| 분류 점수 | 모델이 가장 높게 점수를 준 병해는 무엇인가? |
| 유사 잎 검색 | 모델이 비슷하다고 찾은 잎에도 같은 병해가 붙어 있는가? |
| Grad-CAM과 잎 마스크 | 모델 반응이 강한 위치에 잎과 병반이 함께 보이는가? |
| 종합 확신도 | 근거를 종합했을 때 추가로 확인할 부분이 있는가? |

분류 점수는 100%로 표시됐지만 가장 비슷한 사례 4건 중 같은 병해는 1건이었습니다. 리포트는 종합 확신도를 ‘중상’으로 표시합니다. 이 사례를 검토할 때는 먼저 원본에서 병반을 찾고, 모델 반응 위치가 그 부근에 놓이는지 확인한 뒤, 왜 유사 사례의 병해 라벨이 갈렸는지 비교할 수 있습니다. 히트맵은 모델의 반응 위치를 표시하므로 사진에서 보이는 병반의 실제 경계는 따로 확인해야 합니다. [이 잎의 공개 리포트](https://applecare-orchard.vercel.app/leaf?zone=B&id=b-02)

공개 데모의 저장 데이터에는 검은별무늬병과 겹무늬병이 함께 있는 다른 사례도 있습니다. 분류기는 겹무늬병을 99.9%로 예측했고, 유사 사례 네 건 중 세 건이 그 예측과 일치했습니다. 데이터에는 두 병해가 함께 기록돼 있고 리포트의 종합 확신도는 ‘특정불가’였습니다. 비슷한 잎을 찾았더라도 단일 병해 점수만으로 복합 병해를 식별하기 어렵다는 사례입니다.

## 확인한 결과와 적용 범위

팀은 34명을 대상으로 리포트 제공 여부에 따른 진단 문항 결과를 비교했습니다. 가장 어려운 복합 병해 문항에서 정답률은 리포트 없이 0%, 리포트와 함께 55.8%였습니다. 이 수치는 참가자가 한 문항에서 정답을 고른 비율입니다. 모델 자체의 테스트 정확도나 현장에서 얻은 성과는 별도 지표입니다.

이 비교는 화면에 제공한 근거가 사람의 판단에 어떤 차이를 만드는지 확인하기 위한 것입니다. 후속 평가에서는 단일 병해와 복합 병해를 나누고, 정답 여부와 함께 참가자가 어떤 근거를 보고 판단을 바꿨는지 기록할 수 있습니다. 모델의 예측 성능, 근거가 사용자에게 전달되는 정도, 실제 과수원에서의 판단 효과를 각각 평가해야 어느 단계에 개선이 필요한지 알 수 있습니다.

공개 데모에서는 저장된 사례를 구역과 잎 단위로 확인할 수 있습니다. 새 사진의 실시간 추론은 별도 서버에 연결해야 합니다. 현장에 적용하기 전에는 촬영 조건과 품종이 다른 데이터에서 예측 오류를 확인하고, 확신도가 낮은 사례를 사람이 검토할 때 어떤 근거가 실제로 도움이 되는지 평가해야 합니다. [구역 분석](https://applecare-orchard.vercel.app/analysis) · [새 사진 분석 화면](https://applecare-orchard.vercel.app/analyze)
